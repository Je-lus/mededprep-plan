**Repo investigated (read-only):** `/home/jeramey/projects/mededprep-c` (Laravel/PHP)

**Companion doc:** `distractor-data-investigation.md` (schema map for question banks, response tables, selected-option storage, correct-answer keys, timing, bank discriminators — treated as KNOWN here and extended)

## Summary

MedEdPrep currently persists rich psychometric response data for the legacy quiz/simulator/unit/exit banks: per-question correctness, selected option text, item metadata, student/institution joins, and recent per-question timing. The strongest institutional signals are direct student assignment fields (`users.school_id`, `users.school_branch_id`, `users.instructor_id`) plus cohort/exam-group membership, while the strongest content signals are category/subcategory/exam-level/difficulty relations and unit/exit versioning. The thinnest areas are external outcome linkage and modern psychometrics: NREMT outcomes are sparse/manual with minimal structure, timing is recent-only from February 2026, and Bloom's taxonomy and persisted item statistics such as difficulty index/discrimination are absent.

## Hierarchy map

The direct operational hierarchy for response analysis is:

`schools.id` -> `school_branches.school_id` for campus/location records, and `schools.id` -> `instructor.school_id` for instructors. A student is assigned directly by `users.school_id` -> `schools.id`, `users.school_branch_id` -> `school_branches.id`, and `users.instructor_id` -> `instructor.id`. Those three student columns are the concrete join path from every response bank back to school/location/instructor.

Response joins back up through the parent attempt user id:

- `quiz_attempt_history_question_answers.attempt_history_id` -> `quiz_attempt_history.id` -> `quiz_attempt_history.user_id` -> `users.id` -> `users.school_id` / `users.school_branch_id` / `users.instructor_id`.
- `unit_exam_attempt_history_question_answers.attempt_history_id` -> `unit_exam_quiz_attempt_history.id` -> `unit_exam_quiz_attempt_history.user_id` -> `users.id` -> `users.school_id` / `users.school_branch_id` / `users.instructor_id`. Unit/exit exams also add cohort context through `unit_exam_quiz_attempt_history.unit_exam_id` -> `unit_exam_create_exam.id` -> `unit_exam_create_exam.group_id` -> `groups.id`, and group membership through `group_students.user_id` + `group_students.group_id`.
- `eopa_quiz_attempt_question_answers.eopa_quiz_attempt_history_id` -> `eopa_quiz_attempt_histories.id` -> `eopa_quiz_attempt_histories.user_id` -> `users.id` -> `users.school_id` / `users.school_branch_id` / `users.instructor_id`. EOPA aggregate reports also denormalize those fields directly in `eopa_domain_wise_performances.school_id`, `school_branch_id`, and `instructor_id`.
- `adaptive_exam_attempt_histories.exam_attempt_id` -> `adaptive_exam_attempts.id` and/or `adaptive_exam_attempt_histories.user_id` -> `users.id` -> `users.school_id` / `users.school_branch_id` / `users.instructor_id`.

There is **no single distinct legacy `program` table** tying responses to programs. The closest program/cohort constructs are `groups` for unit/exit cohorts (`groups.created_by` is commented as `program_director_id`), `school_permissions` + `roles.has_schools` for program-director/admin school access, and the newer CE/survey `courses` table linked to schools through `courses_schools` and to surveys through `survey_courses`. For legacy psychometric response analysis, use `users.school_id`, `users.school_branch_id`, `users.instructor_id`, and, for unit/exit only, `unit_exam_create_exam.group_id` / `group_students.group_id` as the concrete hierarchy fields.

## Notable coverage limits

- **Timing is recent-only.** `quiz_attempt_history_time_logs` landed on 2026-02-19, `unit_exit_attempt_history_time_logs` landed on 2026-02-20, and `time_spent` was added to the parent response histories on 2026-02-17/2026-02-20. This matches the prior distractor investigation note that timing covers only a few months of history.
- **Confidence is bank-limited.** Quiz/simulator confidence fields were added on 2025-02-19; unit/exit has `confidence_level`/`reason` in its answer table and `confidence_level_range` from 2024-10-03. EOPA and Adaptive have no persisted confidence columns.
- **Selected options are already captured**, as the prior distractor investigation established. Legacy banks store selected option text (`selected_option`/`answer`), while Adaptive stores normalized `answer_ids` plus `given_answer`.
- **Adaptive is a separate SurveyJS-style adaptive system** and should not be forced into the legacy union. Its items, options, attempts, domains, chapters, and segments are normalized separately.
- **NREMT outcome linkage is thin.** `nremt_attempts.student_id` has no explicit foreign key constraint in the migration, no attempt number, no explicit exam date, and only timestamps plus `result`; `users.nrempt_result` is a sparse/manual summary field with a misspelled column name.
- **Student Code in prior exports is not a database field.** The prior investigation resolved it as Jeramey's manual name-to-number mapping, not `users.registry_number`.
- **Bloom's taxonomy is absent.** A targeted search for `bloom`/`taxonomy` found no migration/model field. Objectives exist as free text on question tables and as an `objectives`/`objective_question` mapping, but there is no Bloom level column.
- **Persisted item psychometric statistics are absent.** There is no persisted `difficulty_index`, point-biserial, discrimination, IRT/Rasch parameter, or p-value column in migrations/models. Some discrimination is computed in `app/Services/Admin/UnitExamStudentService.php`, but it is not persisted as item metadata.
- **Demographics are limited.** The `users` table has `date_of_birth`, `gender`, address/state/country/pincode, but no race/ethnicity, language, socioeconomic, prior education, or employment fields found in the inspected migrations.
- **Branch/location is optional and not FK-enforced** in the original `users` migration. `users.school_branch_id` exists and `school_branches` has a school FK, but `users.school_branch_id` itself is not constrained in `2014_10_12_000000_create_users_table.php`.
- **Program is approximate.** For legacy exams there is no independent program table; use school, branch, instructor, unit/exit group/cohort, and program-director school permissions. The `courses` table is a newer CE/survey construct, not a legacy response-bank program join.
- **Survey scoring is sparse/recent.** `survey_responses.total_questions`, `total_correct`, `score_percentage`, and `passed` were added on 2026-01-14 with nullable fields for backward compatibility with existing survey responses.
- **No flashcard/Leitner bank was found.** `app/Models/Card.php` and `cards` are Stripe/payment card metadata, and `favourite_list` is video favorites, not flashcards.
- **No Pulse-specific schema was found** by targeted search for `pulse` in migrations, models, services, and exports.
