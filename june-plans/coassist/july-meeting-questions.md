# July 2026 CoAEMSP Meeting — Prepared Questions

**Meeting with:** Dr. George Hatch (Executive Director), JD
**Context:** CoAEMSP selected JetPack (Virtual Atlantic) as mandatory AMS. Full implementation anticipated Summer 2027. CoAssist is a free program-side accreditation management tool. Goal: position CoAssist as the program-side complement, not a competitor.
**Prepared:** 2026-06-01

---

## 1. Understanding JetPack's Program-Facing Portal

**1.1** What will the program-facing portal in JetPack actually look like day-to-day for a program director? Will it be a full working environment, or primarily a submission and status-check interface?

> **Why:** If the portal is thin (upload documents, check status, receive decisions), CoAssist owns the entire "internal program work" layer. If the portal is thick (built-in tracking, document drafting, personnel management), we need to understand exactly where CoAssist adds value beyond it.

**1.2** What specific tasks will programs perform inside JetPack's portal? For example — will programs draft narratives in the portal, or upload pre-written documents? Will they manage personnel credentials there, or just confirm them?

> **Why:** The line between "submission interface" and "program management tool" determines CoAssist's positioning. If JetPack expects programs to do substantive work inside the portal, we need to design CoAssist to complement that workflow rather than duplicate it.

**1.3** Austin Farshi's announcement referenced "streamlined workflows" and a "one-stop shop guiding programs through steps, timelines, and documentation." How much of that guidance is built into JetPack versus expectations that programs arrive prepared?

> **Why:** CoAssist's AI gap analysis and narrative drafting features are most valuable if programs are still expected to do heavy prep work before engaging with JetPack. If JetPack hand-holds programs through the entire process, our value prop shifts to operational management (clinical sites, personnel, advisory committees) rather than accreditation prep.

**1.4** The announcement mentioned replacing "manual processes, including downloading spreadsheets and managing file naming conventions." What does the current CoAEMSP submission process look like that JetPack is replacing?

> **Why:** Understanding the current pain gives us a concrete picture of what programs have been struggling with. CoAssist may already solve some of these problems on the program side, which is a talking point. It also reveals what data formats and workflows programs are accustomed to.

**1.5** Will programs have visibility into their compliance status, review timelines, and historical accreditation data through JetPack's portal?

> **Why:** If JetPack gives programs a compliance dashboard, CoAssist's "readiness assessment" features need to be framed as deeper and more actionable. If JetPack only shows high-level status, CoAssist's granular standard-by-standard tracking is clearly differentiated.

---

## 2. Integration & Data Flow

**2.1** Does JetPack have an API or any mechanism for external systems to push or pull data? Has Virtual Atlantic discussed integration capabilities with CoAEMSP?

> **Why:** This is the single most important technical question. If an API exists, we can build a CoAssist-to-JetPack data pipeline and position ourselves as the program-side feeder system. If no API exists, we shift to an export/import model or pursue a formal integration partnership with Virtual Atlantic.

**2.2** What data formats will JetPack expect from programs when they submit self-studies, annual reports, and evidence? Will there be a structured data schema, or primarily document uploads?

> **Why:** If JetPack uses structured data (forms, fields, defined schemas), CoAssist can pre-populate and validate that data before submission. If it is primarily document uploads, CoAssist's value is in generating submission-ready documents. Either way, we need to match the output format.

**2.3** Will programs be required to enter data directly into JetPack, or could data be submitted programmatically from an external system?

> **Why:** This determines whether CoAssist can serve as a front-end that feeds JetPack, or whether programs will need to manually transfer information. Direct programmatic submission would make CoAssist dramatically more valuable as the "where you do the work" tool.

**2.4** The IACBE implementation was referenced as a success story. Do you know whether IACBE's programs use any third-party tools alongside JetPack, or is everything done within the JetPack ecosystem?

> **Why:** IACBE is the closest precedent. If their programs adopted complementary tools, it validates the CoAssist model. If everything runs inside JetPack, we need to understand whether that is by design or by default (because no program-side tools existed in that space).

**2.5** Will there be a single sign-on or shared identity layer? How will program users authenticate?

> **Why:** SSO compatibility affects whether CoAssist can create a seamless experience alongside JetPack. If programs have JetPack credentials, CoAssist could potentially use the same identity provider, reducing friction.

---

## 3. Timeline & Rollout

**3.1** Austin Farshi described the rollout as "iterative and carefully evaluated." What does that look like concretely — a pilot cohort of programs first, then phased expansion? Which programs or program types would go first?

> **Why:** If there is a pilot cohort, we could offer CoAssist as a free complement for those early programs, gathering real-world data on how the two systems work together. Early participation in the rollout = early influence on the ecosystem.

**3.2** What is expected of programs between now and Summer 2027? Will there be a beta period, training sessions, or data migration requirements?

> **Why:** If programs need to prepare for JetPack (e.g., digitize records, organize documents), CoAssist can be the tool they use to get ready. The transition period is a natural adoption window for CoAssist.

**3.3** Is Summer 2027 the target for all programs, or will legacy programs on different accreditation cycles have different timelines?

> **Why:** Programs mid-cycle have different needs than programs approaching initial accreditation or reaccreditation. If the rollout is staggered by cycle, CoAssist can target the cohorts that have the most prep work to do in the near term.

**3.4** What happens to data in the current system during the transition? Will historical self-studies and correspondence be migrated into JetPack?

> **Why:** If historical data does not migrate cleanly, programs lose institutional memory. CoAssist could serve as the bridge — a place where programs maintain their full accreditation history regardless of which AMS CoAEMSP uses.

---

## 4. Program Support & Ecosystem

**4.1** What is the cost model for programs? Does CoAEMSP absorb JetPack's cost, or will programs pay a fee (directly or through increased accreditation fees)?

> **Why:** CoAssist is free. If JetPack adds cost for programs (even indirectly through fee increases), CoAssist's free positioning becomes even more compelling. If CoAEMSP absorbs the cost entirely, there is no cost-driven resistance, but programs may still need a tool optimized for their internal workflow.

**4.2** Will programs be required to use JetPack's portal exclusively, or can they submit data through alternative channels?

> **Why:** If JetPack is the only submission channel, then CoAssist's role is preparation and internal management. If alternative channels remain, CoAssist could potentially serve as a submission pathway itself. The answer determines our ceiling.

**4.3** What training and support will CoAEMSP or Virtual Atlantic provide to programs during and after the rollout?

> **Why:** If training is light, programs will need extra help — CoAssist's AI guidance and built-in standards library becomes a training supplement. If training is robust, we position CoAssist as the "after the training" tool where the daily work actually happens.

**4.4** Has there been feedback from programs about the JetPack announcement? What are program directors most excited or concerned about?

> **Why:** Direct insight into program sentiment tells us exactly what messaging to use. If programs are anxious about complexity, CoAssist is the simplifier. If they are excited about centralization, CoAssist is the tool that makes centralization actually work on the program side.

**4.5** JetPack has not previously worked with EMS education accreditation — their portfolio is pharmacy, business, architecture, and religious schools. How has CoAEMSP ensured the platform will accommodate EMS-specific needs (clinical requirements, psychomotor competencies, field internship tracking)?

> **Why:** EMS accreditation has unique requirements (clinical sites, field internship hours, lead instructor credentialing, medical director engagement). If JetPack is being customized for EMS, we want to understand the scope. If it is a general framework being configured, CoAssist's EMS-specific design (80+ CoAEMSP standards pre-loaded) is a clear differentiator on the program side.

---

## 5. Strategic Positioning (Where CoAssist Fits)

**5.1** We have been building CoAssist as a free program-side accreditation management tool — 80+ CoAEMSP standards pre-loaded, AI gap analysis, narrative drafting, personnel tracking, clinical site management, the whole internal workflow. Programs use it to manage their operations and prepare for accreditation. We see it as naturally complementary to JetPack: CoAssist is where programs do the work, JetPack is where they submit the results. Is that a framing that resonates with where CoAEMSP sees the ecosystem heading?

> **Why:** This is the core positioning pitch, framed as a question. The answer reveals whether CoAEMSP sees JetPack as a total solution or as the receiving end of a larger ecosystem. Their response shapes everything.

**5.2** Is CoAEMSP open to recommending complementary tools to programs? For example, if a tool demonstrably improved submission quality and program readiness, would that be something CoAEMSP would want to make programs aware of?

> **Why:** A CoAEMSP recommendation (even informal) would be transformative for CoAssist adoption. We are not asking for endorsement — we are asking whether the door is open. The answer tells us whether to pursue a formal partnership or grow organically through direct-to-program outreach.

**5.3** If we could demonstrate that programs using CoAssist produce more complete, better-organized submissions — reducing back-and-forth and review workload for CoAEMSP staff — would that be valuable to the organization?

> **Why:** This reframes CoAssist's value from the program's perspective to CoAEMSP's perspective. Accreditors care about submission quality and staff workload. If we can make their reviewers' jobs easier by improving what programs send in, CoAEMSP has a self-interested reason to support CoAssist adoption.

**5.4** Would CoAEMSP be open to a pilot where a small group of programs uses CoAssist alongside JetPack during the rollout, so we can measure whether the combination improves the experience for both programs and CoAEMSP?

> **Why:** This is the concrete ask. A pilot is low-risk for CoAEMSP and high-value for us — it generates data, creates a reference cohort, and opens a direct relationship with the JetPack rollout team. Even a "not right now but maybe later" answer tells us timing.

**5.5** What would the right channel be for us to connect with the Virtual Atlantic team about potential integration? Would CoAEMSP facilitate that introduction, or should we approach them independently?

> **Why:** We need to talk to Virtual Atlantic eventually. Getting CoAEMSP to make the introduction carries weight — it signals to VA that CoAEMSP is interested in the relationship. Going independently is fine too, but we want to know which path George and JD recommend.
